# Post-Implementation Review

実装完了後に自動でサブエージェントによるコードレビューを実施し、重大な問題は自動修正するスキル。

## トリガー条件

以下のいずれかに該当する場合、このスキルが自動発動する：

- 新しいコードを作成・編集した後
- 機能追加・バグ修正・リファクタリングが完了した後
- ユーザーに「実装完了」を報告する直前

## 実行フロー

### Step 1: レビュー対象の差分を特定

サブエージェントに以下を実行させる：

1. **ベースブランチの特定**: `git log --oneline main...HEAD --no-merges` でPRに含まれるコミットを確認
2. **差分取得**: `git diff main...HEAD -- . ':!*.lock' ':!*.sum'` でマージコミットを除外した差分を取得
3. **変更ファイル一覧**: `git diff --name-only main...HEAD` で変更ファイルリストを取得

### Step 2: PRテンプレートの確認

レビュー観点をカスタマイズするために、プロジェクトのPRテンプレートを探す：

1. `.github/pull_request_template.md` を確認
2. `.github/PULL_REQUEST_TEMPLATE/` ディレクトリを確認
3. `docs/pull_request_template.md` を確認

**テンプレートが見つかった場合**: テンプレート内のチェックリストやセクション（例: "テスト", "セキュリティ", "パフォーマンス"）をレビュー観点として活用する。

**テンプレートが見つからない場合**: 以下のデフォルトレビュー観点を使用する。

### Step 3: サブエージェントでレビュー実施

**Agent ツール**を使って `code-reviewer` タイプのサブエージェントを起動する。

サブエージェントへのプロンプトは以下の構成で作成すること：

```
以下のPR差分をレビューしてください。

## レビュー観点
{PRテンプレートがあればその内容、なければデフォルト観点}

## デフォルトレビュー観点（テンプレートがない場合）
1. **正確性・バグ**: ロジックエラー、エッジケースの未処理、nullチェック漏れ
2. **セキュリティ**: インジェクション、XSS、認証・認可の問題、機密情報の露出
3. **パフォーマンス**: N+1クエリ、不要なループ、メモリリーク
4. **エラーハンドリング**: 例外処理の欠如、エラーの握りつぶし
5. **未使用コード**: 未使用のimport、変数、関数
6. **型安全性**: 型エラー、any型の不適切な使用

## 出力形式
以下の形式で結果を返してください：

### 🔴 重大な問題（自動修正対象）
- セキュリティ脆弱性
- 明確なバグ
- 未使用import
- 型エラー

各問題について：
- ファイルパスと行番号
- 問題の説明
- 修正方法の具体的な提案

### 🟡 軽微な問題（指摘のみ）
- 命名の改善提案
- コメントの追加推奨
- リファクタリング提案
- コードスタイルの指摘

各問題について：
- ファイルパスと行番号
- 改善提案

### ✅ 良い点
- 適切な実装パターン
- セキュリティ対策が施されている箇所

## 変更ファイル一覧
{git diff --name-only の結果}

## 差分
{git diff の結果}
```

### Step 4: レビュー結果の処理

サブエージェントからレビュー結果を受け取ったら：

1. **🔴 重大な問題がある場合**:
   - 各問題に対して自動的に修正を実施する
   - 修正内容をユーザーに報告する
   - 例: 未使用importの削除、セキュリティ脆弱性の修正、バグフィックス

2. **🟡 軽微な問題のみの場合**:
   - 指摘事項をユーザーに一覧で報告する
   - 修正するかどうかはユーザーに委ねる

3. **✅ 問題なしの場合**:
   - 「レビュー完了: 問題は見つかりませんでした」と報告する

### レビュー結果の報告フォーマット

```
## 📋 Post-Implementation Review 結果

### 🔴 重大な問題（自動修正済み）
- `path/to/file.ts:42` - [問題の説明] → 修正済み
- `path/to/file.ts:87` - [問題の説明] → 修正済み

### 🟡 軽微な問題（参考）
- `path/to/file.ts:15` - [改善提案]
- `path/to/file.ts:63` - [改善提案]

### ✅ 良い点
- [適切な実装パターンの指摘]
```

## 注意事項

- mainブランチとの差分がない場合（mainブランチ上で作業している場合）は、直近のコミットの差分をレビュー対象とする
- ロックファイル（`*.lock`, `*.sum`）は差分から除外する
- 生成されたファイル（`*.min.js`, `*.map` 等）も差分から除外する
- レビューは日本語で実施する
